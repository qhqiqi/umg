ClassPath · 课路

赛道二：Reverse Product Innovation —— 逆向设计报告

一句话：我们把一个"让人忍不住打开"的产品拆到价值逻辑层，得到一条可迁移的公式，
再用这条公式做了一个新东西——不评课，只交路径。

版本 v1.0 ｜ 2026-11 ｜ 参赛作品：ClassPath（课路）

0. 摘要

项目内容
逆向对象小红书
逆向结论它表面上卖内容，实质上卖的是"决定的代理权"
价值公式V = (E × S × U) / C
迁移领域高校选课决策
原创原型ClassPath：以"路径（Path）"而非"课程（Course）"为最小信息单元
关键取舍继承它的价值逻辑，拒绝它的注意力逻辑

1. 选对象：为什么是它

不是所有"很火的产品"都适合做逆向对象。我们用三条标准筛：

标准含义反例
行为上"忍不住"用户在没有通知、没有任务的情况下主动、无目的地反复打开微信（是基础设施，不是"忍不住"）
结构上"反常识"它成功的原因和它自己宣称的定位不一致淘宝（宣称是商城，行为也确实是购物）
逻辑上"可迁移"核心机制不依赖内容品类，可以搬到别的领域王者荣耀（机制是竞技匹配，迁移价值低）

入选：小红书。 它宣称自己是"生活方式社区"，但用户真正的行为是——在做一个还没做完的决定。

被淘汰的候选，以及淘汰理由：

  • 抖音：机制是"刺激密度"，迁移时极易滑向成瘾设计，伦理成本高，且已被过度复制。
  • 多邻国：机制是"损失厌恶 + 连续记录"，被大量教育产品抄烂，逆向价值低。
  • 拼多多：机制是"社交关系链套利"，迁移到校园场景有合规与伦理风险。
  • 闲鱼：机制是"非标品 + 故事 + 议价"，观察有价值，但它的"忍不住"依赖库存的偶然性，难以稳定设计。

2. 观察：五个"忍不住"的瞬间

以下是我们对自身与周围同学使用行为的切片记录（行为描述，非功能清单）：

  1. 决定悬空时打开。 午饭吃什么、买哪款耳机、周末去哪、暑假怎么安排——不是"我想看内容"，是"我有一个还没做的决定"。
  2. 30 秒内要一个结论，而不是一篇文章。 首图就是结论，标题就是问题（"200 块以内送男朋友"）。用户在接受信息前，先接受了一个"判断"。
  3. 只信"和我像的人"。 同龄、同预算、同城市、同肤质、同基础。官方说明和专业测评反而排在后面——权威在这里是失效的。
  4. 收藏 ≠ 喜欢，收藏 = 这个决定我还没做完。 收藏夹是一个"待办清单"，不是"喜欢清单"。
  5. 搜索框里是问题，不是关键词。 用户输入的是一句处境（"大一 想保研 但数学不好"）。

这五条指向同一个结论：用户来这里不是为了"看"，是为了"不用自己判断"。

3. 拆解：四层机制

层级现象机制被满足的需求
功能层图文笔记、双列瀑布流、搜索、收藏、话题内容供给 + 检索 + 归集找到别人的经验
交互层首图即结论、标题即问题、双列同屏比较、收藏一键把"比较成本"和"承诺成本"同时压到接近零快速收敛选项
心理层决策外包、身份相似信任、收藏夹=心理账户、FOMO把"我要判断"换成"我只要认领一个已经成立的判断"降低判断焦虑
价值层——用"同类人的可执行经验"替代"权威的抽象标准"把决策变成"检索 + 照做"

最重要的那条反常识结论：

小红书不是内容产品，是决策产品。
它的商品不是"笔记"，是"代理权"——替用户完成那次判断。

4. 价值公式

把四层机制压成一个可计算的式子：

V = (E × S × U) / C

E = 经验的可执行度   —— 能不能直接照做（价格、型号、店名、步骤、避雷）
S = 处境相似度       —— 同龄 / 同预算 / 同基础 / 同场景
U = 决策紧迫度       —— 这个决定有多快必须做
C = 检索与验证成本   —— 找到它、确认它、比较它要花多少力气

乘法结构是关键：任何一项为零，整个价值归零。

由此得到三条设计律，它们是后面所有设计决策的依据：

设计律内容反面（做了就退化）
律 1：交付"可执行单元"，不交付"评价"用户要的是"价格 89 元 / 店在二楼 / 别点招牌"，不是"这家不错"只写"好用""避雷"，用户还得再判断一次
律 2：信任来自相似，不来自权威必须携带"处境标签"，并保留瑕疵感变成专家榜单，S 崩塌，退化为内容消费
律 3：给一个近零成本的"承诺动作"收藏的成本≈0，却把内容搬进了"我的计划"只让浏览、不产生计划，用户下次不会回来

一条用来验收迁移方案的反面判据：

  • 若 E 高、S 低 → 变成教程，看完就走。
  • 若 S 高、E 低 → 变成吐槽社区，情绪消费完就散。
  • 只有 E 与 S 同时高，才是可迁移的那部分。

5. 迁移：用五个判据找同构问题

判据说明
① 高紧迫决定必须在有限时间内做出
② 非标信息答案因人而异，没有统一标准
③ 官方信息干燥官方只给字段，不给判断
④ 同类经验海量但不可检索经验存在，但散落在群聊、口碑、过期文档里
⑤ 可被"照做"结论能被直接执行，而不是只能被理解

评分（1–5，满分 25）：

候选领域①②③④⑤合计
校园二手交易3424518
就医挂号5543320
高考志愿填报5554322
健身 / 减脂计划3435419
高校选课4554523

选课胜出，并且多一个别的候选没有的优势：我们自己就是用户，可以自举冷启动（第一批路径由团队成员自己写）。

高考志愿得分接近，但用户不可及、监管敏感，放弃。

6. 从逆向到正向：ClassPath 的设计

6.1 先看现有方案缺什么

现有方案给了什么缺了什么
教务系统课名、学分、教师、时间零决策信息，等于一张"菜单"
评课社区单门课的评价与打分评的是"单门课"，但学生的真实决策是"一组课的搭配 + 一个目标"
群聊 / 学长文档真实、细节多不可检索、会过期、无法横向比较、人一走就断

缺口很明确：没有任何人对"组合"负责。 所有人都在评价一门课，没人对"你为什么这样排这四门课"负责。

6.2 把对象换掉：Course → Path

这是本作品唯一的、也是最重要的创新点——不是界面创新，是对象创新：

Path = 一个目标
     + 4~6 门课（含可执行字段）
     + 时间预算（周学时）
     + 一句"为什么这样排"
     + 一个可验证结果（绩点区间 / 拿到什么 / 踩了什么坑）
     + 一句"这条路径不适合谁"

评价一门课，回答的是"这门课好不好"。 分享一条路径，回答的是"你上个学期到底是怎么过的，我能不能照着过一遍"。

6.3 三条设计律的落地

设计律在产品里的具体形态
律 1：可执行单元每门课强制携带：学分、周学时、考核形态（考试/大作业/实验）、是否点名、是否早八、给分区间、工具与教材、组队要求
律 2：相似优先每条路径强制标注处境标签：专业、年级、目标、每周可投入时长、绩点段位。列表按相似度排序，不按热度排序
律 3：零成本承诺"收藏路径" → 自动生成"我的课表草案"，含时间冲突检测与周学时预算；"照抄"把浏览直接变成计划

6.4 三个"比原产品更克制"的决定

逆向设计最容易犯的错，是把对方的成瘾机制一起抄过来。我们做了三条反向选择：

  1. 不做无限流。 入口是"你的目标"，不是"猜你喜欢"。路径有尽头，匹配完就该关掉。
  2. 显示负向证据。 每条路径都有一句"这条路径不适合谁"。原产品永远不会告诉你"你不该买"。
  3. 内置预算护栏。 周学时超过你声明的可投入时长，直接红牌；早八 ≥ 3 门、学分低于毕业线，都会告警。
一句话总结取舍：继承它的价值逻辑（E×S/U），拒绝它的注意力逻辑（无限流、FOMO）。

6.5 数据飞轮

路径发布 → 被收藏 → 被照抄 → 学期末回填真实结果 → 路径可信度被校准 → 更靠前

只有被照抄过且完成回填的路径，才能进入首页。这让"可信度"来自验证，而不是来自流量。

7. 原型

7.1 技术

项选择理由
形态单文件 Web（prototype/index.html）零依赖、零构建，双击即可演示，评委现场能点

7.2 功能清单

#功能对应设计律
F1目标选择（保研 / 就业 / 科研 / 转专业 / 稳绩点 / 实习）入口即目标，不做推荐流
F2可投入时长滑杆（12–28 h/周）让 S（处境相似度）可计算
F3路径卡按相似度排序，显示匹配理由律 2
F4路径详情：为什么这样排 + 逐门课可执行字段 + 避雷 + 不适合谁律 1
F5收藏 / 照抄 → 生成"我的课表草案"律 3
F6草案页：学分统计、周学时预算、时间冲突检测、早八计数告警预算护栏
F7"方法"抽屉：把逆向设计的公式与三条设计律嵌进产品让推理过程可见
F8学期末回填入口（占位，期末周开放）数据飞轮的入口

7.3 主流程（5 步）

选目标 → 调时间预算 → 看匹配路径 → 打开一条路径（读"为什么"）→ 收藏/照抄 → 课表草案与告警

7.4 60 秒演示脚本

时间动作要说的话
0–8s打开首屏"选课的时候，教务系统只告诉你课名和学分，但你要决定的是：这学期怎么过。"
8–18s选"保研冲绩点"，滑杆拉到 20h"你只回答两个问题：想要什么，能投入多少。"
18–30s看路径列表"出来的是路径，不是课程评价。每条都标了作者的处境，和我们像不像，一眼就能看出来。"
30–45s打开"保研稳绩点""它不告诉你这门课好不好，它告诉你：为什么这四门放在一起、哪门会拖垮你、这条路径不适合谁。"
45–60s点照抄 → 草案页红牌"照抄之后它直接变成课表，并且告诉你：周一有 1 处时间冲突，周学时还超了 1 小时。——这就把浏览变成了一个真的决定。"

8. 评估

8.1 与现有方案对比

维度教务系统评课社区群聊/文档ClassPath
信息单元课程字段单课评价零散经验路径（组合 + 目标）
是否可执行否部分是但不可检索是，字段化
相似度匹配无弱靠人情显式标签 + 排序
时间成本可视化无无无有，含护栏告警
负向证据无少量有但不可靠强制"不适合谁"
可信度来源权威热度熟人被照抄 + 回填验证

8.2 成功指标

指标定义目标
照抄率打开路径 → 生成课表草案≥ 25%
收藏→草案转化收藏 → 照抄≥ 40%
回填率学期末完成结果回填的路径占比≥ 30%
护栏拦截被预算/冲突告警拦下的草案数观察项（越高说明护栏越有用）
负向证据阅读率展开"不适合谁"的比例≥ 60%

8.3 风险与对策

风险说明对策
冷启动没有路径就没有用户团队自举首批 30 条；按"目标"而非"课程"组织，少量数据也能覆盖主要需求
真实性作者夸大给分强制回填 + "被照抄后回填"加权；显示样本量而不是单一评分
路径同质化所有人都抄同一条按处境标签分组排序；对"高照抄低回填"的路径降权
隐私课表与绩点敏感只存聚合区间（如 85–92），不存精确分数；作者可匿名
被当成"抄作业"工具削弱自主判断每条路径必须写"为什么"，并显示"不适合谁"

10. 诚实的边界

本报告中标注为"观察"的内容来自设计者的自省与周边同学的行为讨论，不是统计抽样结论； 示例路径中的课程、教师、分数均为虚构示意数据，用于演示交互，不代表任何真实院校。

以下三条是假设，需要在真实用户中验证：

  1. H1：学生在选课时，真正需要的是"组合方案"而非"单课评价"。（若否，Path 这个对象就立不住）
  2. H2：处境标签的相似度排序，比热度排序更能提升照抄率。
  3. H3：内置预算护栏不会显著降低使用意愿（即"劝退"不会劝退用户）。
